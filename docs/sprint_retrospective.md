# Sprint 1 Retrospective

## What Worked

Using the existing PolenRep process made the requirements realistic.

Configuring the automation and checking received emails provided
observable evidence that the notification worked.

## What Slowed Us Down

The relationship between the PLD stories and the PAD prototype was
not clearly defined before configuration started. This led to repeated
clarification of what PAD was intended to demonstrate.

Terminology was inconsistent across the requirements, configuration
instructions and tests, making the intended scope harder to follow.

## Improvements for the Next Iteration

Before configuration, write a short scope statement naming the
requirements covered and the test result expected for each function.

Use the same names for roles, requests and decisions throughout the
documentation. Explain unfamiliar configuration concepts before use.
